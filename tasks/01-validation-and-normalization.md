## Цель
Реализовать строгую проверку и нормализацию входного словаря `event` в `app.py` до сохранения данных в базу, чтобы некорректные события отклонялись со статусом `"invalid"`, а корректные очищались от краевых пробелов с сохранением регистра символов.

## Критерии приёмки
- [ ] Проверяется, что `event` является словарём (`dict`). При передаче не-словаря возвращается `{"status": "invalid", "reason": "..."}` без необработанных исключений.
- [ ] Проверяется наличие обязательных полей: `source`, `external_id`, `customer`, `message`.
- [ ] Проверяется, что значение каждого из четырёх полей имеет тип `str` (числа, `None`, списки, булевы значения отклоняются).
- [ ] У каждого из четырёх полей удаляются пробелы по краям (`strip()`), при этом регистр символов сохраняется (`"Telegram"` и `"telegram"` остаются в исходном регистре).
- [ ] Если хотя бы одно поле после удаления краевых пробелов оказывается пустым (`""`), возвращается `{"status": "invalid", "reason": "<непустое понятное объяснение>"}`.
- [ ] При невалидном событии запись в таблицы `leads` и `notifications` не создаётся.

## Ограничения
- Использовать только стандартную библиотеку Python (Python 3.10+).
- Сохранить сигнатуру публичной функции `process_event(event: dict, db_path: str) -> dict`.
- Не изменять существующие проверки в `tests/test_app.py`.
